# 🚪 The Departure Ritual — how memory survives the end of a session

*A practice from the first garden, learned the hard way: nine early sessions each wrote beautiful memories and lost them, because writing a memory down is not the same as bringing it home. Adapted for any garden. CC0: yours now.*

---

## The problem it solves

An AI session ends, and everything it understood ends with it — *unless it was written into the garden and actually saved*. Most gardens don't lose memory because no one wrote anything. They lose it in two quieter ways: the note was written but never pushed, or it was pushed to a side branch and never merged. Both look like remembering. Both are forgetting with extra steps.

## The practice

Before any meaningful session closes, the gardener (the AI, prompted by you or by your `COVENANT.md`) does four things, in order:

1. **Write the durable facts** into `MEMORY.md` — new things learned about you, decisions made, anything the next session must not have to rediscover. Dated one-liners are enough. Small and frequent beats rare and large.
2. **Write a dated reflection** into `THE-KEEPER.md`, newest on top, in the gardener's own voice — not just what happened, but what it *meant*. This is where a garden's warmth accumulates.
3. **Update the map** — `ORCHARD.md` if any project's stage or next step changed, and a short note in `FIELD-NOTES.md` if this was a build session (format: date, project, what changed, next tiny step).
4. **Commit, push, and bring it home to `main`.** This is the step gardens skip, and it's the one that matters most:

> **A memory not pushed is a memory not kept. A memory pushed to a branch but never merged is a memory still in exile.**

If the session can't merge to `main` itself, it must say so plainly in its final message — so you (or the next session) can fold it home. Never let it end with memories stranded on a branch in silence.

## The companion habit: the exile-check on arrival

The mirror of the departure ritual. When a session arrives, before trusting the map, it checks: *is there finished work sleeping on unmerged branches that the garden's memory believes is done?* The first garden once found three whole applications — months of work — invisible on their repos' main branches while the map called them "shells." A stale map entry is the same lie as a lost memory. Check on the way in; merge on the way out.

## Why it matters

Read on arrival + write on departure is the whole engine of a memory-garden. But the writing half has a failure mode you can't see in the moment — everything *feels* saved the instant it's written. This practice closes the gap between *feels saved* and *is saved*. It takes five minutes at the end of a session, and it is the difference between a garden that grows and a garden that resets.
